## Chạy và nghiệm thu

Từ root project, cập nhật môi trường API theo lockfile:

```bash
uv sync --project api --frozen
```

Dừng launcher cũ nếu đang chạy cùng cổng. Chạy:

```bash
uv run --project api --frozen python -m api.dev --verification
```

Mở [Môi trường](http://127.0.0.1:8000/#environment). Nếu cổng bận, thêm `--app-port 8100 --api-port 8101` rồi mở app ở 8100.

1. Chọn **VieNeu**, **Môi trường thật** → **Kiểm tra môi trường**. Thấy từng thành phần và lời nhắc chưa nạp/thử model.
2. Đổi sang **Piper**, **Edge TTS**, **OpenAI TTS**, bấm kiểm tra sau mỗi lần đổi. Kết quả cũ được xóa khi đổi lựa chọn để không nhầm provider.
3. Chọn **Piper → Giả lập thiếu thư viện** → kiểm tra. Thấy nhãn **KẾT QUẢ CÓ GIẢ LẬP**, lỗi đúng thư viện provider và hướng bỏ giả lập.
4. Chọn **Giả lập thiếu model** → kiểm tra. Thấy model thiếu và cách xử lý, không xóa model thật. Tình huống này chỉ áp dụng Piper/VieNeu.
5. Chọn lại **Môi trường thật** → kiểm tra. Nhãn giả lập biến mất, kết quả trở về trạng thái máy hiện tại.
6. Trong terminal launcher nhập `api stop` → bấm kiểm tra. Thấy lỗi kết nối có thể thử lại. Nhập `api start` → bấm kiểm tra lại và nhận kết quả.
7. Chạy launcher không có `--verification`: trang Môi trường vẫn hoạt động nhưng không có lựa chọn fixture; API cũng từ chối scenario giả lập.

Không cần tạo workspace T02 cho flow này: fixture T03 chỉ thay kết quả kiểm tra trong bộ nhớ. Chọn **Môi trường thật** để reset tình huống. Không có dữ liệu mới cần xóa.
