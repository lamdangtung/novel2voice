# T04 — Schema và nâng cấp checkpoint

Đã triển khai và kiểm tra tự động theo ủy quyền tiếp tục backlog. Schema SQLModel version 1 gồm truyện/chương/artifact/job và tham chiếu checkpoint cũ; bảng web có prefix n2v_*, không ghi đè jobs/chunks/artifacts của CLI. Có session commit/rollback, foreign key, unique số chương trong truyện.

Chạy lại tại gốc project:

```bash
uv run --project api --frozen python -m api.storage self-check --workspace migration-demo
```

Cần FFmpeg/ffprobe để tạo audio fixture T02. Lệnh chỉ tạo bản sao fixture trong `.verification/workspaces/migration-demo/migration-xxxx/`; không nhận đường dẫn DB sản xuất. Tự kiểm tra: snapshot checkpoint → backup → nâng cấp → so count/hash → nâng cấp lần hai → gây lỗi trên bản sao khác → khôi phục backup chính xác. Mỗi lần chạy có thư mục mới; reset toàn workspace bằng công cụ T02 và xác nhận RESET migration-demo nếu muốn xóa kết quả kiểm thử.

Kết quả: 2 jobs, 2 chunks, 1 artifact legacy trước/sau không đổi; database/audio nguồn không đổi; lần hai already_current; failure_restored_exactly=true. Không tạo truyện/chương hoặc mapping MP3 tự động. [Báo cáo](T04/report.json).

6 test storage đạt: dữ liệu/rollback, nâng cấp lặp lại, từ chối tại chỗ/target đã có/link, FK/unique và snapshot bao gồm committed WAL. `migrate_copy` là hàm nội bộ copy-only; không có endpoint nâng cấp DB thật. Migration thực tế cần bản sao và kiểm chứng riêng; không tự gắn MP3 bằng số trong tên file.
