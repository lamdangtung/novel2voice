## Mở flow trên web

Dừng launcher cũ nếu đang dùng cùng cổng. Chạy từ root project:

```bash
uv run --project api --frozen python -m api.dev --verification
```

Mở **http://127.0.0.1:8000/#verification**. Nếu cổng đang dùng, thêm `--app-port 8100 --api-port 8101`, rồi mở app ở cổng 8100.

Flow nghiệm thu:

1. Thấy banner **CHẾ ĐỘ KIỂM THỬ** trên mọi màn hình và menu **Kiểm thử offline**. Không có dữ liệu truyện thật được đưa vào màn hình này.
2. Giữ tên `demo` hoặc đặt tên mới, bấm **Tạo dữ liệu mẫu**. Thấy đường dẫn vùng kiểm thử, **2 bộ truyện, 18 file**, phiên bản `t02-v1`.
3. Chọn **Không gây lỗi**, delay 0 → **Chạy self-check offline**. Thấy **Đạt**, **3 lần gọi TTS, 1 lần translator**, 3 audio hợp lệ và bản dịch giả lập.
4. Bấm phát một âm thử, tải báo cáo JSON và xem nhật ký. Mỗi lần gọi có sự kiện started/completed hoặc failed, chapter_id, chunk_index và hash input.
5. Chọn **TTS giả lập**, lỗi theo lần gọi thứ 2 → chạy lại. Thấy **Có lỗi** chủ động ở A/2, audio A/1 và A/en/1 vẫn được giữ. Không kết luận đây là lỗi model thật.
6. Chọn **Translator giả lập** → lỗi lần gọi 1 → chạy lại. Thấy 2 audio VI, 1 lần dịch lỗi và không có bản dịch hoàn thành.
7. Có thể đổi sang lỗi theo chương, hoặc đặt delay 800ms để quan sát trạng thái đang chạy. API health và trang khác vẫn phản hồi; đây chưa phải queue/worker của T15.
8. Nhập chính xác **RESET demo** (hoặc tên workspace đang chọn) → **Reset dữ liệu kiểm thử**. Xác nhận sai thì nút không bật; server cũng kiểm tra lại.
9. Đổi về Không gây lỗi, delay 0 rồi self-check. Kết quả logic trở lại như bước 3; run bắt đầu lại từ `run-0001`.
10. Reload trang, chọn lại workspace nếu cần; fixture và báo cáo vẫn tồn tại. Tạo workspace khác rồi reset demo: workspace khác giữ nguyên dữ liệu.

Chạy app không có `--verification` để kiểm tra chế độ thường: không có banner/menu kiểm thử; `/api/v1/verification/workspaces` trả 404 và không xuất hiện trong OpenAPI.

## Flow CLI có thể chạy lại

Tại root project, không cần chạy web server:

```bash
uv run --project api --frozen python -m api.verification init --workspace demo
uv run --project api --frozen python -m api.verification self-check --workspace demo
uv run --project api --frozen python -m api.verification reset --workspace demo --confirm 'RESET demo'
uv run --project api --frozen python -m api.verification self-check --workspace demo
```

Mỗi lệnh in JSON. Self-check chuẩn trả `status: passed`, `tts_calls: 3`, `translator_calls: 1`, audio có stream/thời lượng dương qua ffprobe. `init` trên workspace đã có chỉ đọc lại, không ghi đè kết quả.

Gây lỗi hoặc delay mà không sửa provider sản xuất:

```bash
uv run --project api --frozen python -m api.verification self-check --workspace demo --fail-provider tts --fail-on-call 2
uv run --project api --frozen python -m api.verification self-check --workspace demo --fail-provider tts --fail-chapter A/2
uv run --project api --frozen python -m api.verification self-check --workspace demo --fail-provider translator
uv run --project api --frozen python -m api.verification self-check --workspace demo --delay-ms 800
```

CLI exit code: **0** = thành công; **1** = self-check có lỗi chủ động; **2** = đường dẫn/xác nhận/cấu hình/môi trường không hợp lệ. Khi translator được chọn, lần gây lỗi mặc định là 1; self-check chỉ có một lần gọi translator.

Kiểm tra ranh giới reset:

```bash
uv run --project api --frozen python -m api.verification reset --workspace ./output --confirm 'RESET output'
```

Kết quả: exit 2, `UNSAFE_WORKSPACE`; không tạo/xóa/sửa dữ liệu ở output. `input`, `models`, path ngoài vùng, symlink, hardlink và marker không hợp lệ cũng bị từ chối.

## Giới hạn và cách dùng cho task sau

- Đây là phòng kiểm thử offline có self-check ngắn, không phải job nền sản xuất, checkpoint dịch hoặc bộ đánh giá chất lượng giọng đọc.
- Mỗi run giữ kết quả riêng trong `runs/run-xxxx/`, log tại `calls.jsonl`, báo cáo tại `report.json`; `latest-report.json` dùng cho UI. Reset xóa kết quả/log của workspace được chọn và tạo lại fixture; không reset toàn bộ root.
- Khi tiến trình bị kill cưỡng bức giữa self-check, run có thể chưa có report hoàn chỉnh. Chạy lại tạo run mới hoặc reset workspace; chưa hứa resume của T15–T20.
- Provider giả lập chỉ được import tường minh từ `api.verification`; không sửa logic registry/provider sản xuất để gây lỗi. T15/T17 có thể dùng FakeTTSProvider.generate_batch; fail_on_calls điều khiển đoạn và fail_on_chapters điều khiển chương.
- Marker và vùng root cố định bảo vệ khỏi thao tác nhầm, không phải sandbox chống một tiến trình độc hại đang đồng thời sửa filesystem bằng quyền của chính người dùng.
